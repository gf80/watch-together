# Watch Together

Сервис совместного просмотра: комната, общий чат, единая пауза, перемотка и
синхронизация плеера. Файлы не загружаются на сервер — он только проксирует поток.

## Возможности

- Комнаты по короткой ссылке `/r/<id>`, до 16 участников.
- Чат, список зрителей, индикатор набора текста, история в SQLite.
- Общие play/pause и перемотка. Источник задаёт только хост.
- Синхронизация всегда включена: мягкая подстройка скоростью, жёсткий seek при
  дрейфе больше 1.9 с, авто-пауза у отстающих при буферизации. Общая скорость
  зафиксирована на 1.0, отключить синхронизацию нельзя — сервер не принимает
  команды `rate` и `autopause`.
- Источники: прямые ссылки на mp4/webm/mkv/mov/аудио, HLS-плейлисты, страницы
  YouTube и других сайтов через `yt-dlp` (DASH пересобирается через ffmpeg).
- Кнопки-иконки с подсказками: пуск, ±10 секунд, звук, полный экран, источник,
  копирование ссылки, удаление.
- Хост удаляет комнату кнопкой-корзиной: остальные сразу возвращаются в лобби.
- На телефоне видео и чат видны одновременно, страница не прокручивается.

Интерфейс собран из чистых HTML/CSS/JS без сборки; тема — плоский тёмный
графит с одним сдержанным акцентом, hls.js подключается с CDN.

## Запуск

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe run.py
```

Открыть http://127.0.0.1:8000 , создать комнату и отправить друзьям ссылку.
Для доступа из локальной сети `run.py` уже слушает `0.0.0.0`.

Опционально: `ffmpeg` в PATH — нужен только для потоков, которые нельзя отдать
напрямую (например, YouTube DASH). Прямые ссылки и HLS работают без него.

## Развёртывание в Docker

Dockerfile ставит всё нужное сам: Python-зависимости, `ffmpeg` из репозитория
Debian и свежий бинарник `yt-dlp` из релизов GitHub. Собирается в один образ с
непривилегированным пользователем и healthcheck.

```bash
docker compose up -d --build
```

Открывать http://<ip-сервера>:8000 . Обновление после `git pull`:

```bash
git pull && docker compose up -d --build
```

База и кэш лежат в `./data` на хосте и переживают пересборку образа. Каталога
может не быть — `docker compose` создаст его, но он будет принадлежать root, и
контейнер (uid 1000) не сможет писать. Тогда один раз:

```bash
mkdir -p data && sudo chown -R 1000:1000 data
```

Остановить и удалить контейнер, не трогая данные:

```bash
docker compose down
```

### HTTPS и WebSocket

Синхронизация идёт через WebSocket, поэтому сайт обязательно должен быть
открыт по HTTPS (или напрямую по HTTP в доверенной сети) — под публичным
HTTP браузер не даст подключиться. Проще всего поставить reverse proxy с
сертификатом, а сам контейнер оставить на localhost:

```yaml
services:
  watch-together:
    build: .
    restart: unless-stopped
    ports:
      - "127.0.0.1:8000:8000"
    volumes:
      - ./data:/app/data
```

Пример для Caddy (`Caddyfile`):

```
watch.example.com {
    reverse_proxy 127.0.0.1:8000
}
```

Caddy сам выпустит сертификат и проксирует WebSocket без дополнительных
настроек. Для nginx нужен явный блок:

```nginx
location / {
    proxy_pass http://127.0.0.1:8000;
    proxy_http_version 1.1;
    proxy_set_header Upgrade $http_upgrade;
    proxy_set_header Connection "upgrade";
    proxy_set_header Host $host;
    proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
    proxy_set_header X-Forwarded-Proto $scheme;
    proxy_read_timeout 3600s;   # видео-стрим не должен рваться по таймауту
    proxy_buffering off;        # иначе буферизация съест весь поток
}
```

Контейнер запускается с `--proxy-headers`, поэтому эти заголовки доезжают до
приложения корректно.

### Ресурсы сервера

ffmpeg и одновременные видео-потоки едят CPU. Для домашней сети или 1–2
комнат хватит 1 ядра и 1 ГБ RAM. Бюджет в расчёте на одну комнату:
ffmpeg только на время пересборки DASH, дальше сервер просто проксирует поток
и почти ничего не считает.

## Запуск через туннель и SSH

Если сервер на другой машине, проброс порта в VS Code или другом редакторе
подходит, но есть два ограничения:

- Нужен именно TCP-проброс. Редакторные HTTPS-туннели (Codespaces, Remote
  Tunnels, ngrok) часто не пропускают WebSocket, а комната работает через
  `/ws/...` — чат и синхронизация тогда не поедут. Проверяется так: если в лобби
  видно «на связи», а не «переподключение…», туннель годный.
- Видео идёт через сервер целиком, поэтому чем длиннее путь (туннель, мобильный
  интернет, VPN), тем заметнее задержка. Синхронизация честно показывает дрейф в
  индикаторе и при большой задержке постоянно перематывает всех.

Надёжный способ для себя и друзей — SSH-туннель на localhost, тогда WebSocket
идёт напрямую и задержка минимальна:

```powershell
ssh -N -L 8000:127.0.0.1:8000 user@сервер
```

Затем открывать http://127.0.0.1:8000 . Друг другу отдавайте адрес из локальной
сети (`http://<ip-сервера>:8000`), а не туннель.

## Настройки

Все переменные имеют префикс `WT_`.

| Переменная | По умолчанию | Смысл |
| --- | --- | --- |
| `WT_DATA_DIR` | `./data` | база SQLite, кэш и локальные файлы |
| `WT_DB_PATH` | `<WT_DATA_DIR>/watch_together.sqlite3` | путь к базе |
| `WT_ALLOW_PRIVATE_PROXY` | `0` | `1` разрешает потоки с localhost и локальной сети |

## ffmpeg и yt-dlp

Нужны, чтобы вставлять ссылки на страницы, а не на файлы:

```powershell
winget install --id Gyan.FFmpeg -e
.\.venv\Scripts\python.exe -m pip install -U yt-dlp
```

ffmpeg ищется в PATH, а если там пусто — в типовых папках установки
(`%LOCALAPPDATA%\Microsoft\WinGet\Packages\Gyan.FFmpeg_*`, `Program Files`,
`bin` рядом с проектом). Поэтому после `winget install` перезапускать терминал
не обязательно, достаточно перезапустить сервер. Точный путь виден в лобби
при наведении на строку окружения, а также в `GET /api/capabilities`
(`ffmpeg_path`).

ffmpeg нужен только когда у сайта нет готового файла с видео и звуком
(например, DASH с раздельными дорожками YouTube). Прямые ссылки, HLS и
прогрессивные mp4 с сайтов вроде VK работают без него и без скачивания.

Если yt-dlp отвечает «getaddrinfo failed», это не поломка: домен не
разрешается. Проверьте, открывается ли ссылка в браузере на этой машине, —
часто youtube.com просто заблокирован в сети.

По умолчанию прокси блокирует приватные адреса (защита от SSRF). Если фильмы
лежат на NAS или в домашней сети, запускайте с `WT_ALLOW_PRIVATE_PROXY=1`:

```powershell
$env:WT_ALLOW_PRIVATE_PROXY = "1"
.\.venv\Scripts\python.exe run.py
```

## Как это работает

Сервер держит эталонное состояние: `status`, `position`, `anchor` (момент
фиксации позиции), `rate` и монотонный `seq`. Клиент считает ожидаемую позицию
как `anchor + (now - anchor_at) * rate` и подстраивается под неё. Команды
paused/play/seek приходят всем участникам через WebSocket; буферизация у
конкретного клиента автоматически ставит общую паузу, чтобы никто не отставал.
Поля `rate`/`auto_pause` остаются в схеме для хранения, но всегда равны `1.0` и
`true`: сервер отклоняет соответствующие команды.

Поток отдаётся через `/api/stream/<room>/<url>`: поддерживаются `Range`,
CORS, `Referer`, перезапись URL внутри HLS-манифеста и allowlist хостов,
обнаруженных в манифесте. Доступ к потоку есть только у участников комнаты.

## Тесты

```powershell
.\.venv\Scripts\python.exe -m pip install -r requirements-dev.txt
$env:WT_ALLOW_PRIVATE_PROXY = "1"   # для локальных тестовых потоков

.\.venv\Scripts\python.exe tests\smoke.py        # API, WebSocket, HLS, Range, SSRF
.\.venv\Scripts\python.exe tests\persistence.py  # перезапуск сервера и SQLite
.\.venv\Scripts\python.exe tests\browser.py       # реальный браузер, 51 проверка
.\.venv\Scripts\python.exe -m ruff check app tests run.py
```

Тесты ждут сервер на `http://127.0.0.1:8123` (переопределяется `WT_BASE_URL`),
поэтому сначала запустите его:

```powershell
$env:WT_ALLOW_PRIVATE_PROXY = "1"
.\.venv\Scripts\python.exe -m uvicorn app.main:app --port 8123
```

`tests/browser.py` использует установленный Edge через Playwright и локально
сгенерированный WAV, внешняя сеть не нужна. По умолчанию браузер открывается
видимым окном — так надёжнее работает ввод с клавиатуры; для фонового прогона
включите `$env:WT_HEADLESS = "1"`. Скриншоты падают в `tests/`, включая
мобильный вид 390×844.

Если PowerShell некорректно показывает русский вывод, добавьте
`$env:PYTHONIOENCODING = "utf-8"`.

## Ограничения

- Синхронизация точная насколько позволяет сам видеоплеер: браузер не даёт
  контролировать скорость точнее примерно ±8 %.
- Звук всегда индивидуальный: общий регулятор громкости не транслируется, кнопка
  mute действует только на ваш браузер.
- Форматы, которые не умеет воспроизводить браузер (некоторые mkv, раздельные
  дорожки DASH), требуют ffmpeg для пересборки.
- Страницы, где есть DRM (Netflix и подобные), не поддерживаются.

Смотрите только то, на что у вас есть права.
